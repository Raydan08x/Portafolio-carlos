BrewPi Control: Monitoreo IoT con Node-RED y PostgreSQL

10 JUL 2026
IoT Node-RED PostgreSQL Vibe Coding / IA

El Contexto: Necesitábamos un sistema confiable para monitorear las temperaturas de fermentación en tiempo real utilizando microcontroladores ESP32 y una Raspberry Pi como servidor central. The Context: We needed a reliable system to monitor fermentation temperatures in real-time using ESP32 microcontrollers and a Raspberry Pi as the central server.

El Desafío: El principal reto técnico fue asegurar la persistencia de los datos ante cortes de red y la orquestación del flujo de mensajes MQTT sin sobrecargar la base de datos PostgreSQL, la cual corría en hardware limitado (Raspberry Pi). The Challenge: The main technical challenge was ensuring data persistence during network outages and orchestrating the MQTT message flow without overloading the PostgreSQL database running on limited hardware (Raspberry Pi).

La Solución: Implementé una arquitectura basada en Node-RED como middleware. Node-RED se encarga de suscribirse a los tópicos MQTT, limpiar los datos y agruparlos en lotes antes de hacer las inserciones en PostgreSQL. Esto redujo las operaciones de escritura en un 40% y mejoró la estabilidad del sistema a largo plazo. El desarrollo y la iteración de la interfaz SCADA se realizaron mediante un proceso de Vibe Coding asistido por IA, acompañado de revisión, pruebas y ajustes técnicos. The Solution: I implemented an architecture based on Node-RED as middleware. Node-RED subscribes to MQTT topics, cleans the data, and batches it before inserting into PostgreSQL. This reduced write operations by 40% and improved long-term system stability. The SCADA interface was developed and iterated through an AI-assisted Vibe Coding process, accompanied by technical review, testing, and refinement.

Prototipo Sierra Dorada: Vibe Coding y Generación con IA

28 JUN 2026
Vibe Coding OpenCode

El Contexto: Desarrollo rápido de un prototipo funcional para un cliente corporativo (Sierra Dorada) reduciendo drásticamente el tiempo de maquetación inicial. The Context: Rapid development of a functional prototype for a corporate client (Sierra Dorada) drastically reducing initial mockup time.

El Desafío: Trasladar los requerimientos de diseño de alto nivel a prompts efectivos para modelos de IA sin perder control sobre la semántica del HTML y la especificidad del CSS. La IA a menudo genera código inflado o no responsivo si no se guía correctamente. The Challenge: Translating high-level design requirements into effective prompts for AI models without losing control over HTML semantics and CSS specificity. AI often generates bloated or non-responsive code if not guided correctly.

La Solución: Adopté una estrategia de "Vibe Coding" iterativa. En lugar de pedir la página completa, usé herramientas como Antigravity para modularizar los componentes (Navbar, Footer, Hero) en prompts separados, asegurando que el código generado se apegará a variables CSS estándar y HTML semántico vanilla. The Solution: I adopted an iterative "Vibe Coding" strategy. Instead of asking for the full page, I used tools like Antigravity to modularize components (Navbar, Footer, Hero) into separate prompts, ensuring the generated code adhered to standard CSS variables and semantic vanilla HTML.

E-commerce Sierra Dorada: Gestión de Estado en Vanilla JS

20 JUN 2026
JavaScript DOM CSS Grid

El Contexto: Desarrollo del proyecto integrador de Generation, construyendo una tienda en línea completa desde cero sin utilizar frameworks reactivos. The Context: Development of the Generation capstone project, building a complete online store from scratch without using reactive frameworks.

El Desafío: Mantener el carrito de compras sincronizado entre múltiples pestañas y vistas, asegurando que los cambios de estado (agregar, eliminar, cambiar cantidad) se reflejaran instantáneamente en el DOM sin recargar la página. The Challenge: Keeping the shopping cart synchronized across multiple tabs and views, ensuring state changes (add, remove, change quantity) reflected instantly in the DOM without reloading the page.

The Solution: I designed a centralized state management pattern using localStorage and JavaScript CustomEvents. This allowed creating loosely coupled components that react to cart changes efficiently and maintainably.

Trendy Shop: Filtrado Dinámico y Consumo de APIs REST

15 MAY 2026
Fetch API Asynchronous JS

El Contexto: Una Hackathon en equipo donde el objetivo era construir una tienda virtual responsiva que consumiera un catálogo de productos desde un backend externo. The Context: A team Hackathon where the goal was to build a responsive virtual store that consumed a product catalog from an external backend.

El Desafío: Manejar la latencia de la red, los errores de la API y renderizar cientos de productos de manera eficiente en el navegador sin bloquear el hilo principal. Además, se requería un filtrado complejo por categorías y precios en tiempo real. The Challenge: Handling network latency, API errors, and rendering hundreds of products efficiently in the browser without blocking the main thread. In addition, complex real-time filtering by categories and prices was required.

La Solución: Implementé Promesas asíncronas con async/await y bloques try/catch para un manejo de errores robusto. Para el rendimiento, apliqué debouncing en las entradas de búsqueda y un patrón de delegación de eventos para los filtros, minimizando los event listeners en el DOM. The Solution: I implemented asynchronous Promises with async/await and try/catch blocks for robust error handling. For performance, I applied debouncing on search inputs and an event delegation pattern for filters, minimizing DOM event listeners.

Task Manager: Delegación de Eventos y Manipulación del DOM

25 MAR 2026
Event Listeners CRUD

El Contexto: Aplicación fundamental tipo To-Do list para afianzar los conceptos de manipulación directa del DOM (Crear, Leer, Actualizar y Eliminar). The Context: A fundamental To-Do list application to consolidate concepts of direct DOM manipulation (Create, Read, Update, and Delete).

El Desafío: Al agregar nuevas tareas dinámicamente, los botones de "Eliminar" y "Editar" de esos nuevos elementos no respondían a los event listeners previamente adjuntados. The Challenge: When adding new tasks dynamically, the "Delete" and "Edit" buttons of those new elements did not respond to the previously attached event listeners.

La Solución: Descubrí y apliqué el patrón de Event Delegation (Delegación de eventos). En lugar de agregar un listener a cada botón individual, agregué un solo listener a la lista padre (ul), capturando y procesando los eventos a través del event bubbling basándome en el target seleccionado. The Solution: I discovered and applied the Event Delegation pattern. Instead of adding a listener to each individual button, I added a single listener to the parent list (ul), capturing and processing events through event bubbling based on the selected target.
